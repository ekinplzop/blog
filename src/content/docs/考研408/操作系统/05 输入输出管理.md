# 第 5 章 输入输出（I/O）管理

## 5.1 I/O 设备与 I/O 控制器

### 一、I/O 设备的分类与特征

I/O 设备是负责将数据输入/输出计算机系统的外部设备，由**机械部件**（执行具体I/O操作）与**电子部件**（设备控制器/印刷电路板）组成。

| 分类维度 | 设备类别 | 典型代表 | 核心考点与特性（习题重点） |
| :--- | :--- | :--- | :--- |
| **按使用特性** | **人机交互类**<br>**存储设备**<br>**网络通信** | 鼠标、键盘、显示器<br>磁盘、固态硬盘、光盘<br>网卡、调制解调器 | 交互类速度较慢；存储与通信类通常要求高速传输 |
| **按传输速率** | **低速设备**<br>**中速设备**<br>**高速设备** | 键盘、鼠标（字节/s）<br>激光打印机（KB/s）<br>磁盘、光盘（MB/s） | 决定了系统应采用何种 I/O 控制方式与之匹配 |
| **按信息交换单位**<br>==*(高频考点)*== | **块设备**<br>(Block Device) | 磁盘、SSD | • **传输快、可寻址**（能随机读写任意块）<br>• 以“块”（如 512B~4KB）为单位传输，常用 DMA 方式 |
| | **字符设备**<br>(Character Device) | 键盘、鼠标、打印机 | • **传输慢、不可寻址**（流式顺序访问，==不能指定字节地址寻址==）<br>• 以“字符”（字节）为单位传输，==常用中断驱动方式== |
| **按资源共享属性**<br>==*(易错考点)*== | **独占设备** | 打印机 | 一段时间内只允许一个进程独占访问；分配不当==可能引起死锁== |
| | **共享设备** | 磁盘、SSD | • 宏观并发、微观交替；==**必须是可寻址和可随机访问的设备**==<br>• 分配共享设备==**绝不会引起死锁**== |
| | **虚拟设备** | SPOOLing 打印机 | 通过软件技术把一台独占物理设备变换成多台对应的逻辑设备 |

> [!tip] **设备标识符概念辨析（题13）**
> - **绝对号（物理设备名）**：系统对每台物理设备统一进行的唯一编号，作为底层区分和识别硬件的代号，用户编程不可直接更改。
> - **相对号（逻辑设备名）**：用户编程时使用的设备代号（如 `printer1`），由系统通过**逻辑设备表（LUT）**映射到物理绝对号。

### 二、I/O 控制器（设备控制器）

I/O 控制器是 CPU 与设备机械部件之间的中介，用于接收 CPU 指令并控制机械部件执行操作。

#### 1. I/O 控制器的四大核心功能（题04、05）
1. **接收和识别 CPU 命令**：内部有**控制寄存器**，存放 CPU 发来的命令及参数。
2. **向 CPU 报告设备状态**：内部有**状态寄存器**，记录设备当前就绪/忙碌/出错状态。
3. **数据交换**：内部有**数据寄存器**，暂存来自 CPU 或设备的数据（起到缓冲匹配速度的作用）。
4. **地址识别**：识别控制器内部各个寄存器的物理/逻辑地址。

#### 2. I/O 控制器的三大组成部分
* **CPU 与控制器之间的接口**：数据线、控制线、地址线（实现 CPU 与控制器通信）。
* **I/O 逻辑**：==**真正用于实现设备控制功能的部件**==（负责对 CPU 的命令译码并向设备发出具体电气控制信号）。
* **控制器与设备之间的接口**：包含数据、控制、状态信号线（实现控制器与外设机械部件通信）。

#### 3. DMA 控制器的内部寄存器组成（题10避坑）
- **命令/状态寄存器（CR/SR）**：接收 CPU 指令与存放设备状态。
- **内存地址寄存器（MAR）**：存放数据在主存中的起始地址。
- **数据缓冲寄存器（DR）**：暂存输入/输出的数据。
- **数据计数器（DC）**：记录传送的字数/字节数。
- ==**避坑**==：**堆栈指针寄存器（SP）属于 CPU**，绝不属于设备控制器/DMA 控制器！

### 三、I/O 端口编址方式对比（核心大题/选择题重点）

I/O 端口即 I/O 控制器内部的各寄存器（控制、状态、数据寄存器）。

| 编址方式 | 编址机制与地址空间 | 操作指令与编程 | 优缺点对比 |
| :--- | :--- | :--- | :--- |
| **内存映射 I/O**<br>*(统一编址)* | 寄存器与主存统一编址；各寄存器**占用一部分主存地址空间** | 使用**普通的访存指令**即可访问寄存器（如 `MOV`、`LOAD`、`STORE`） | • **优点**：指令丰富，简化硬件设计<br>• **缺点**：占用了主存地址空间，访存速度稍慢 |
| **寄存器独立编址**<br>*(I/O 独立编址)* | 寄存器拥有**完全独立的 I/O 地址空间**，与内存地址互不干扰（地址可重叠） | 必须设置**专门的 I/O 指令**才能访问（如 x86 的 `IN`、`OUT` 指令） | • **优点**：不占用主存地址空间，程序意图清晰<br>• **缺点**：I/O 指令少，操作不灵活，需额外控制线 |

### 四、通道、控制器与设备从属关系（题07、14）

1. **四级从属关系**：
   $$\text{CPU} \longrightarrow \text{通道} \longrightarrow \text{设备控制器} \longrightarrow \text{设备}$$
   - **通道控制设备控制器，设备控制器控制设备工作**（均为一对多从属）。
2. **本质属性**：
   - ==**通道技术是一种硬件机制**==（本质是一个专用的“弱化版 CPU”），与 CPU 共享内存。
   - 相比之下，SPOOLing、缓冲池则是**操作系统软件技术**。

## 5.2 I/O 控制方式（四大控制方式演进）

核心追求目标：**尽量减少 CPU 介入频率，提高 CPU 与 I/O 设备的并行度**。

### 四大控制方式全景横向对比

| 方式 | 传送单位 | 数据流向 | CPU 干预时机与频率 | 用户进程状态（题20） | 核心优缺点 / 考点特性 |
| :--- | :---: | :---: | :--- | :---: | :--- |
| **① 程序直接控制**<br>*(查询/轮询法)* | 字 / 字节 | 设备 $\leftrightarrow$ CPU $\leftrightarrow$ 内存 | **极高**（CPU 全程忙等循环轮询状态） | ==保持运行态==<br>*(不阻塞)* | • 硬件最简单<br>• ==CPU 与 I/O 完全串行，CPU 利用率极低== |
| **② 中断驱动方式** | 字 / 字节 | 设备 $\leftrightarrow$ CPU $\leftrightarrow$ 内存 | **较高**（每传输完一个字/字节发一次中断） | ==进入阻塞态==<br>*(等待中断)* | • CPU 与外设实现部分并行<br>• 高速外设下频繁中断会压垮 CPU |
| **③ DMA 方式**<br>*(直接存储器存取)* | **块**<br>*(连续的一个/多个块)* | 设备 $\leftrightarrow$ 内存<br>*(直通总线，不经 CPU)* | **很低**（仅在传送开始前和整块传送结束时介入） | ==进入阻塞态==<br>*(等待中断)* | • 建立在**主存和设备之间**的直接数据通路<br>• 仅适用于**连续物理块**传输 |
| **④ 通道控制方式** | **一组块**<br>*(可离散分布)* | 设备 $\leftrightarrow$ 内存<br>*(直通总线)* | **极低**（仅在整组通道程序执行完成后发中断） | ==进入阻塞态==<br>*(等待中断)* | • 具备专用通道指令程序<br>• 实现了最大程度的软硬件并行 |

---

### 核心考点流程与机制深剖

#### 1. 程序直接控制方式（轮询忙等）
* **流程**：CPU 发读命令 $\to$ **循环读取 I/O 状态寄存器**（未准备好则继续轮询） $\to$ 准备好后，CPU 从数据寄存器读取数据到 CPU 内部寄存器 $\to$ 写入主存 $\to$ 循环直至全部字读完。
* **考点陷阱**：整个轮询过程中，**进程不释放 CPU，始终处于运行态**，绝不进入阻塞态。

#### 2. 中断驱动方式（进程阻塞等待）
* **流程**：CPU 发出 I/O 命令后**立即调度其他进程运行**，原进程进入==阻塞态== $\to$ 外设准备好数据后向 CPU 发出中断请求 $\to$ CPU 暂停当前程序，执行中断处理程序将数据读入主存 $\to$ 唤醒原阻塞进程进入==就绪态==。
* **瓶颈**：由于**每个字都要中断一次**，CPU 频繁被打断保存现场，不适用于高速设备。

#### 3. DMA 方式的工作三阶段与时序（2017 统考真题 26）
DMA 数据传输由 DMA 控制器硬件全权负责，分为三个严格的时序阶段：
1. **预处理阶段（CPU 参与，内核态，原进程处于运行态）**：
   - CPU 向 DMA 控制器的寄存器指明目标内存起始地址（MAR）、传送字数（DC）、磁盘物理扇区地址，并向控制寄存器（CR）发出启动磁盘命令。
   - 随后请求 I/O 的进程**转入阻塞态**，CPU 调度其他进程执行。
2. **数据传输阶段（CPU 完全不参与，纯硬件进行）**：
   - DMA 控制器接管总线，以**块**为单位，直接在**磁盘设备和内存缓冲区**之间建立高速数据传输通路。
3. **后处理阶段（CPU 参与，内核态，原进程处于阻塞态）**：
   - 整块数据传输完毕后，**DMA 控制器向 CPU 发出中断请求**。
   - CPU 响应后转入执行 **“DMA 结束”中断服务程序**（此时原请求进程仍在阻塞态，中断处理程序检查传输无误后将其**唤醒进入就绪态**）。

> [!note] **2017 统考真题标准执行顺序**
> $$\text{② 初始化 DMA 控制器并启动磁盘} \longrightarrow \text{③ 从磁盘传输一块数据到内存} \longrightarrow \text{① DMA 控制器发出中断请求} \longrightarrow \text{④ 执行“DMA 结束”中断服务程序}$$

## 5.3 I/O 软件层次结构

> **核心设计理念**：高层抽象统一、低层具体适配；自顶向下逐层调用，隐藏硬件细节。

```
     I/O 请求（自顶向下）
            │
            ▼
┌────────────────────────┐
│     用户层 I/O 软件     │  ── 提供库函数接口（如 printf、scanf、fopen）
├────────────────────────┤
│    设备独立性软件      │  ── 逻辑设备表（LUT）映射、系统调用处理、设备保护、缓冲管理、设备分配
├────────────────────────┤
│      设备驱动程序      │  ── 每类设备专配：将系统调用参数/抽象命令翻译为设备控制器的操作命令
├────────────────────────┤
│      中断处理程序      │  ── 底层硬件中断捕获、保存现场、执行数据转储并唤醒进程
└────────────────────────┘
            │
            ▼
┌────────────────────────┐
│     硬  件  设  备     │  ── 机械部件 + 设备控制器（执行物理动作）
└────────────────────────┘
            ▲
            │
     I/O 应答（自底向上）
```

### 各层次的核心职责与考点归纳

| 层次 | 所在空间 | 核心职责与考点细节（做题必背） |
| :--- | :---: | :--- |
| **① 用户层 I/O 软件** | **用户态** | 向上提供方便友好的调用接口（如 C 语言的 `printf`、`read` 库函数包装） |
| **② 设备独立性软件**<br>*(设备无关软件)* | **内核态**<br>*(I/O系统)* | • ==**核心功能：逻辑设备到物理设备的映射**==：用户使用逻辑设备名（相对号），系统通过**逻辑设备表（LUT）**映射到物理设备名（绝对号），实现**设备独立性（可重定向/可移植性）**<br>• 实现设备保护、系统统一缓冲管理、独占设备的安全分配与回收 |
| **③ 设备驱动程序**<br>==*(高频考点)*== | **内核态**<br>*(I/O系统)* | • ==**驱动程序数量按“设备类别”配置，非按设备台数配置**==（如 2 台同型绘图机 + 3 台同型打印机只需要 **1 + 1 = 2 个驱动程序**，题15）<br>• 负责==**将系统调用参数翻译成具体的设备操作命令**==（题16）<br>• 直接向设备控制器的寄存器写入读/写命令（题17） |
| **④ 中断处理程序** | **内核态**<br>*(I/O系统)* | • 当 I/O 操作完成或硬件出错时，硬件向 CPU 发送中断请求<br>• 负责执行数据转储（主机获取输入/输出），并**调用唤醒原语将阻塞的请求进程唤醒** |
| **⑤ 硬件设备** | **物理层** | 执行机械动作，并在操作结束或出错时向 CPU 发出硬件中断信号 |

### 统考真题深层考点与易错避坑总结

#### 1. I/O 处理中的软硬件分工（题19）
* **硬件完成（中断隐指令）**：关中断、保存断点（PC 与 PSW）、根据中断向量引出中断服务程序（CPU 模式切入内核态）。
* **软件完成（中断处理程序）**：保护通用寄存器现场、==**主机获取设备输入（读写控制器数据寄存器）**==、恢复现场、开中断返回。

#### 2. 中断处理完毕后的返回去向（题21）
* ==**中断处理结束后，不一定会返回被中断的原进程！**==
* *原因*：中断处理程序唤醒了等待 I/O 的阻塞进程。如果被唤醒的进程**优先级高于当前被中断的进程**，系统在中断返回前会触发进程调度程序，**直接切换调度给新就绪的高优先级进程执行**。

#### 3. 键盘输入场景的程序响应顺序（2010 统考真题 23）
* 当本地用户敲击键盘登录系统时，**首先获得键盘输入信息的程序是【中断处理程序】**（键盘按下触发硬件中断，CPU 立刻响应进入中断处理程序读取按键扫描码，之后再层层上传给驱动、系统调用以及用户登录程序）。

#### 4. 用户程序发起磁盘读写的完整时序流（2011 统考真题 24）
$$\text{用户程序} \longrightarrow \text{系统调用处理程序（设备无关层）} \longrightarrow \text{设备驱动程序} \longrightarrow \text{中断处理程序}$$

#### 5. 设备分配应考虑的考量因素（题12）
* **设备分配必须考虑的三大问题**：
  1. **设备的固有属性**：独占设备（需防死锁）、共享设备（可寻址随机访问）、虚拟设备（SPOOLing）。
  2. **设备分配算法**：先来先服务、优先级高者优先等。
  3. **设备分配的安全性**：安全分配方式（进程请求分配后进入阻塞，天然防死锁）、不安全分配方式（银行家算法安全预判）。
* ==**不属于考量因素**==：**“及时性”**（及时性是调度算法的指标，不是设备分配的属性）。

## 5.4 I/O 定量计算专题（CPU 占用百分比）

### 核心通用计算公式

$$
\text{CPU 用于 I/O 中断的百分比} = \frac{\text{单位时间内中断处理的总耗时}}{\text{总时间}} = \text{每秒发生的中断次数} \times \text{单次中断处理耗时}
$$

$$
\text{每秒发生的中断次数} = \frac{\text{每秒传输的数据总量（字符数或字节数）}}{\text{每次中断传输的数据量}}
$$

---
