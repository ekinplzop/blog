**磁盘初始化：**  
**Step 1：进行低级格式化（物理格式化）**，将磁盘的各个磁道**划分为扇区**。一个扇区通常可分为头、数据区域（如512B大小）、尾三个部分组成。管理扇区所需要的各种数据结构一般存放在头、尾两个部分，包括扇区校验码（如奇偶校验、CRC循环冗余校验码等，校验码用于校验扇区中的数据是否发生错误）
**Step 2：将磁盘分区**，每个分区由若干柱面组成（即分为我们熟悉的 C盘、D盘、E盘）  
**Step 3：进行逻辑格式化**，创建文件系统。包括创建文件系统的根目录、初始化存储空间管理所用的数据结构（如 位示图、空闲分区表）


引导块：
1. **ROM 容量极小且昂贵**：操作系统内核动辄几百 MB 到数 GB，主板上的 ROM 芯片放不下。
2. **便于升级更新**：操作系统经常打补丁或重装。如果写死在 ROM 里，更新系统就得更换物理硬件芯片。
3. **两级装入策略（折中解法）**：
    - 主板 ROM 里只放一段极其微小的初始化代码（**BIOS / UEFI**）；
    - 磁盘的固定位置（**引导块**）存放真正的系统引导代码；
    - 磁盘的普通数据区存放庞大的**操作系统内核镜像**。
>所有格式化好的磁盘都有 0 扇区和保留引导区，但只有**系统盘（启动盘）的引导块中才写入了可执行的引导程序。

坏块是磁盘上因物理损坏而无法读写数据的扇区。考研 408 中，坏块管理的核心考点是**两大解决策略的对比**：

1. **软件级管理（简单系统）**：由**操作系统**在文件系统（如 FAT 表/空闲块表）中标记出坏块并避开，**对操作系统不透明**；坏块会导致系统可用容量**减少**
2. **硬件级管理（复杂系统/扇区重映射）**：由**磁盘控制器**内部利用出厂预留的备用扇区进行硬件替换，**对操作系统完全透明**。可用容量**保持不变**（消耗预留备用空间）



### 磁盘读写
#### 1. 寻找时间（寻道时间）

$$
T_s = s + m \times n
$$

* $s$：磁臂启动时间（固定的硬件常数，算法无法改变）。
* $m$：磁头跨越一个磁道所需的时间常数。
* $n$：跨越的磁道数。
* **考点结论**：磁盘调度算法（SSTF、SCAN 等）**唯一能减少的，其实就是红框里的移动磁头时间（$m \times n$）**，启动时间 $s$ 无法被算法消除。

#### 2. 延迟时间（旋转延迟时间）

$$
T_r = \frac{1}{2r}
$$

* $r$：磁盘转速（如 7200 rpm / 120 转/秒）。
* **考点结论**：盘片只能单向匀速旋转，平均延迟为转半圈时间。算法无法让盘片加速或倒车，因此**调度算法无法优化延迟时间**。若想优化延迟时间，必须靠**扇区交替编号 / 错位命名**。

#### 3. 传输时间

$$
T_t = \frac{b}{r \times N}
$$

* $b$：本次读写的总字节数。
* $N$：一个磁道能容纳的总字节数。
* $r$：磁盘转速。


### 磁盘调度算法

以磁盘请求队列 55，58，39，18，90，160，150，38，184， 为例， 磁头初始位于磁道100。

FCFS（先来先服务）：
- 总移动距离： （45+3+19+21+72+70+10+112+146） = 498
- 平均寻道长度： 498 / 9 = 55.3
SSTF（最短寻找时间优先）：
- 贪心策略。每次优先响应与当前磁头距离最近的请求。
- **总移动距离**：(10+32+3+16+1+20+132+10+24)=248
- **平均寻道长度**：248/9≈27.6248/9≈27.6
- SSTF 追求局部最优但非全局最优，容易导致远端磁道（如 184）发生**饥饿**现象。

 SCAN（扫描算法 / 传统电梯算法）：
-  磁头沿当前方向一路服务，==**必须走到该方向的最外端点**==，哪怕端点没有请求也必须走到底，然后掉头反向服务。
- 总移动距离：   (50+10+24+16+110+32+3+16+1+20) = 282
- **平均寻道长度**：282/9 = 31.33

 LOOK 算法（电梯算法的改进版）：
 - 走到请求队列的最外端点就可以。
 - 总移动距离： 84 + 166 = 250
 - 平均寻道长度： 250 / 3 = 27.8


C-SCAN（循环扫描算法）
- **调度规则**：为了解决两端磁道等待时间不均的问题，规定磁头==**只能单向服务**==（例如只能向大方向读写），走到最外端点后，**立刻直接快速返回到最内端点（0）**，返回途中不提供任何读写服务，接着再向大方向扫描。
- **408 核心考点：算不算返回距离** 

C-LOOK 算法（循环扫描改进版）
- **调度规则**：结合了 LOOK 和 C-SCAN 的优点。单向服务，走到该方向的**最大请求（184）后，不必走到 200；直接**快速返回到另一侧的最小请求（18）**，也不必退到 0 号磁道！

---

| 优化层面 | 核心技术手段 | 核心消除的开销 / 作用原理 |
| :--- | :--- | :--- |
| **磁头寻道层** | 磁盘调度算法（SSTF, SCAN, C-LOOK） | 减少**寻找时间 Ts**（减少跨越磁道数） |
| **扇区旋转层** | **扇区交替编号**、**柱面错位命名** | 减少**延迟时间 Tr**（避免错过扇区多转一圈） |
| **系统内存层** | **磁盘 Cache**、**预读机制**、**延迟写** | **减少真实访盘次数**（用高速内存替代慢速外设） |
| **设备控制层** | 使用 **DMA 方式**、**I/O 通道** | 释放 CPU，实现硬件自主高速批量数据流转 |
| **物理阵列层** | **RAID 磁盘阵列**（条带化并行） | **多盘并行 I/O**，大幅提高整机传输带宽 |
| **物理介质层** | 更换为 **SSD 固态硬盘** | 机械寻道与旋转延迟彻底降为 0 |


## 固态硬盘（SSD）

### 一、物理原理与基本组成

1. **核心原理**：
   - 基于**闪存技术**（Flash Memory），本质上属于**电可擦除可编程只读存储器（EEPROM）**。
   - 具备**非易失性**（断电后数据不丢失）与**随机寻址**能力。

2. **两大核心组成部分**：
   - **闪存翻译层（FTL, ）**：SSD 的“大脑”，负责将操作系统发来的逻辑块号（LBA）翻译映射到物理闪存的对应“页（Page）”。
   - **存储介质（NAND 闪存）**：
     $$\text{SSD} \longrightarrow \text{多个闪存芯片} \longrightarrow \text{多个块（Block）} \longrightarrow \text{多个页（Page）}$$

---

### 二、读写特性与“异地更新”瓶颈

| 维度 | 闪存页（Page） | 闪存块（Block） |
| :--- | :--- | :--- |
| **操作单位** | **读、写的最小物理单位**（通常 4KB） | **擦除（Erase）的最小物理单位**（通常包含几十~几百页） |
| **磁盘对应** | 相当于传统机械硬盘的**扇区** | 擦除单位，无法单页擦除 |
| **关键约束** | **只能在“已擦除的干净页”上写入一次**；若页内已有数据，必须先整块擦除才能重写（读无限次，写需擦除）。 |

> [!important] **读快写慢与写放大**
> - **读操作**：直接寻址目标页读取，极快（微秒级）。
> - **写操作**：若目标页已有数据，不能就地覆盖，FTL 必须将该块的其他有效页复制到新块，并对原块执行整块擦除（**异地更新 **），因此写操作相对较慢。

---

### 三、SSD 与传统机械硬盘（HDD）全方位对比

| 对比维度       | 固态硬盘（SSD）                              | 传统机械硬盘（HDD）                         |
| :--------- | :------------------------------------- | :---------------------------------- |
| **物理寻址机制** | 纯电子芯片电路寻址，**无寻道时间、无旋转延迟**              | 机械臂移动（寻道）+ 盘片高速旋转                   |
| **读写性能**   | 随机读写与顺序读写均极快（尤其是小文件随机读）                | 随机读写慢（机械寻道耗时 2~20ms），顺序读较快（连续存取有优势） |
| **抗震与功耗**  | 无机械运动部件，抗震抗摔、安静无噪音、功耗低                 | 怕剧烈震动跌落，运行时有电机旋转噪音与发热               |
| **擦写寿命限制** | **每个闪存块有擦写次数上限**（如几千~数万次），反复擦写会导致块损耗坏掉 | 扇区磁性颗粒不会因正常读写次数而耗尽物理寿命              |
| **价格成本**   | 每 GB 单位造价相对较高                          | 每 GB 单位造价极低（适合冷数据海量仓储）              |

### 四、磨损均衡技术

为了防止某些热点数据块频繁擦写导致过早损坏，SSD 固件引入了磨损均衡算法：

1. **核心思想**：
   将整盘的擦除操作**均匀分布**到每一个闪存块上，避免局部坏死，最大化延长 SSD 的使用寿命。

2. **两大均衡策略**：
   - **动态磨损均衡：
     - 当写入新数据时，FTL **优先挑选累计擦除次数较少的新块/空闲块**写入。
   - **静态磨损均衡（更优秀）：
     - 系统自动监测各块的磨损度。
     - 将原本长期存放非热点数据（“只读不写”的静态数据，如系统文件、只读照片）从老旧磨损块迁移走；
     - **让写入寿命已损耗较大的老旧块来承担只读任务，把磨损较少的新块腾出来用于频繁写入**。
