# 云计算复习资料精简背诵版

> 目标：不是删题，而是把原答案压成“考场能写出来”的关键词版。带 `*` 或“学习通限定”的题优先背。

## 背诵总口诀

- 云计算：**资源上网，按需服务，弹性计费**。
- 分布式：**多节点协同，核心矛盾是一致性、可用性、容错性**。
- 虚拟化：**把物理资源抽象成逻辑资源**。
- 分布式存储：**多机联网，对外像一个整体存储**。
- SDN：**转控分离，集中控制，开放接口**。
- 云原生：**容器、微服务、DevOps、持续交付**。
- 云件：**软件主体在云端，终端只负责交互显示**。

# Ch1 云计算概述

## 课内复习

### *1 云计算的定义是什么？

云计算是一种通过互联网把动态可扩展、通常虚拟化的计算资源，以服务形式按需提供的计算模式。

关键词：**互联网、虚拟化、按需、弹性、服务化、付费使用**。

### *2 云计算的公共特征有哪几个？

1. 弹性伸缩  
2. 快速部署  
3. 资源抽象  
4. 按用量收费  
5. 宽带访问

### 3 云计算按部署方式和服务类型分哪几类？

- 部署方式：公共云、私有云、社区云、混合云、行业云等。
- 服务类型：IaaS 基础设施即服务、PaaS 平台即服务、SaaS 软件即服务。

### *4 如何从三元认识论理解云计算？

从三层理解：

1. **商业模式**：IaaS、PaaS、SaaS 等服务模式。
2. **计算范式**：由经济因素和技术因素共同决定，可看作横向云体、纵向云栈。
3. **实现方式**：依靠数据中心和软件定义数据中心实现，计算、存储、网络都虚拟化并服务化。

### 5 云计算作为计算范式分成哪两种结构？

- 横向：**云体逻辑结构**。
- 纵向：**云栈逻辑架构**。

### *6 开源软件、自由软件、免费软件的区别与联系是什么？

- 开源软件：公开源码，允许学习、修改、分发，但不一定免费。
- 自由软件：强调运行、复制、分发、学习、修改的自由，要求更严格。
- 免费软件：免费使用，但通常不开源，也不一定允许修改。
- 联系：都可能免费；区别在于**源码是否开放、权利是否自由、价格是否为零**。

## 课外思考

### *1 计算系统是如何演变成今天的云计算的？

主机计算 → 小型机 → C/S → 分布式计算 → 网格计算 → 效用计算 → 云计算。  
本质是资源从本地独占走向网络化、服务化、按需化。

### 2 如何理解“开源是种方法论”？

开源不仅是代码公开，更是一种通过开放共享、社区协作、集体智慧和组织引导解决复杂问题的方法。

### 3 开源技术如何促进云计算发展？

1. 降低私有云建设门槛。  
2. 方便按需求定制云服务。  
3. 推动云服务创新。  
4. 促进用户、厂商、社区协作，形成开放生态。

# Ch2 分布式计算

## 课内复习

### 1 分布式计算的定义和特征是什么？

分布式计算是多个软件或多台计算机通过网络协同工作、共享信息和资源的计算方式。

特点：资源共享、负载均衡、任务可放在最合适节点执行、可靠性和扩展性更高。

### *2 什么是 ACID 原则？

数据库事务四原则：

- A 原子性：要么全做，要么全不做。
- C 一致性：事务前后数据满足约束。
- I 隔离性：并发事务互不干扰。
- D 持久性：提交后永久保存。

### 3 什么是 CAP 理论？

分布式系统中，**一致性 C、可用性 A、分区容错性 P** 三者最多同时满足两个。

- C：所有节点同一时刻数据一致。
- A：每个请求都能得到正常响应。
- P：网络分区或消息丢失时系统仍能运行。

### 4 什么是 BASE 理论？

BASE 是 CAP 的延伸，放弃强一致，追求最终一致：

- Basically Available：基本可用。
- Soft State：软状态，允许中间状态。
- Eventual Consistency：最终一致。

### *5 如何理解最终一致性？

系统允许短时间不一致，但经过同步后，所有副本最终达到一致。  
记忆：**过程松，结果紧**。

### *6 各类分布式存储的区别与联系是什么？

- 结构化存储：关系表、SQL、强一致，如 MySQL。
- 非结构化存储：文件/对象，重扩展，如 GFS、HDFS。
- 半结构化存储：KV、NoSQL，对随机访问更友好。
- In-memory 存储：数据在内存，低延迟，如 Redis、Memcached。
- NewSQL：兼顾 SQL、ACID 和分布式扩展，如 Spanner。

### *7 各类分布式计算的区别和联系是什么？

1. MPI 消息传递：适合高性能计算，节点间显式通信。
2. MapReduce/Dataflow：把计算抽象成 Map、Reduce、Filter 等数据流，适合大规模批处理。
3. 图计算：把任务抽象为图，适合 PageRank、社交网络等图数据。

联系：都是把大任务拆到多节点并行执行；区别在于抽象模型和适用场景不同。

### 8 分布式存储和分布式计算的区别与联系是什么？

- 分布式存储：解决数据如何分散保存、复制、容错。
- 分布式计算：解决任务如何拆分、调度、并行执行。
- 联系：大数据系统通常“存算结合”，计算靠近数据可减少网络开销。

## 课外思考

### 1 为什么日常生活中的分布式系统越来越多？

业务量变大、单机不够用；需要高可用、容错、扩展；模块化后开发部署更快，团队协作更好。

### *2 CAP 为什么不能同时保证？不同组合有什么场景？

网络分区发生时，如果仍要响应请求，就可能读到旧数据，牺牲一致性；如果坚持一致，就要阻塞请求，牺牲可用性。

- CP：重一致和容错，可能不可用；如银行、强一致数据库。
- AP：重可用和容错，允许最终一致；如 DNS、购物车、社交系统。
- CA：无分区时可实现，但真实分布式系统通常必须考虑 P。

### 3 区块链作为分布式系统的新理念是什么？

传统分布式数据库默认节点可信、协作；区块链默认节点不可信、相互制约。  
它用共识机制在无中心环境下维护账本，重点解决“节点本身不可靠”的问题。

# Ch3 云计算架构

## 课内复习

### *1 云计算中的工作负载有哪几种模式？特征是什么？

1. 时开时停：资源间歇使用，传统自建容易闲置浪费。
2. 用量迅速增长：用量随时间持续上升，云可弹性追加资源。
3. 瞬时暴涨：短时间出现峰值，云可快速扩容后释放。
4. 周期性增减：负载有规律波动，云可按周期自动伸缩。

### 2 如何避免云计算资源“超配”问题？

用 IT 租赁/云计算替代一次性购买，按需申请、按量付费、自动扩缩容，避免资源长期闲置。

### *3 如何理解“云栈”和“云体”？

- 云体：云计算的物质基础，是服务器、网络、存储等资源集合。
- 云栈：云平台及其运行环境，在云体上支持应用发布、运行、监控、调度和伸缩。

一句话：**云体是资源，云栈是平台**。

### *4 什么是软件定义的数据中心？特点是什么？

SDDC 是把计算、存储、网络、安全等数据中心资源虚拟化，并通过软件统一管理和交付的数据中心。

特点：标准化、全面、自适应、自动化、恢复能力强。

### *学习通限定 5 什么是 REST 设计风格？

REST 是面向 Web 的架构风格，强调统一接口、客户机/服务器分离、无状态连接、组件独立发布和良好伸缩性。

### *学习通限定 6 简述 OpenStack 产生的原因？

云计算发展需要一个开源平台来统一管理计算、存储、网络等资源。OpenStack 因此产生，用于搭建和管理私有云、公有云，降低成本并提高灵活性。

## 课外思考

### 1 云计算架构如何演化？

中央集权架构 → C/S → 中间层 → B/S → C/S 与 B/S 混合 → SOA 面向服务架构 → 云计算架构。

### 2 如何理解“软件定义一切”？

软件通过抽象和控制硬件、网络、数据中心等资源，使系统功能由软件灵活定义。其基础是硬件能力提升和网络连接能力增强。

# Ch4 虚拟化技术

## 课内复习

### *1 什么是虚拟化技术？有哪三种类型？

虚拟化是对计算资源进行抽象，把物理资源变成可管理、可分配的逻辑资源。

类型：服务器虚拟化、网络虚拟化、桌面虚拟化。

### *2 全虚拟化和半虚拟化的区别是什么？

- 全虚拟化：客户操作系统无需修改，不知道自己被虚拟化；兼容性好，但开销较大。
- 半虚拟化：客户操作系统需要修改，与虚拟化层协作；性能可能更好，但兼容性差。

### *3 硬件虚拟化技术有哪些代表？

GPU 虚拟化、FPGA 虚拟化、RDMA 虚拟化、NVM 虚拟化。

### *4 什么是轻量级虚拟化技术？代表是什么？

轻量级虚拟化是在共享宿主机内核的基础上隔离应用运行环境的技术。代表：容器，典型是 Docker。

### *学习通限定 5 寄居架构和裸金属架构虚拟机监控器是什么？区别是什么？

- 寄居架构 Type 2：运行在宿主操作系统之上，如 VMware Workstation、VirtualBox。
- 裸金属架构 Type 1：直接运行在物理硬件上，如 VMware ESXi、Hyper-V。
- 区别：寄居型依赖宿主系统，适合桌面/测试；裸金属性能更好，适合服务器生产环境。

## 课外思考

### 1 虚拟化如何提高资源利用率？

把多个应用/系统整合到同一物理资源池中，按需分配、动态迁移、隔离运行，从而减少闲置和重复采购。

### *2 轻量级虚拟化相对传统虚拟化的优势和不足是什么？

- 优势：启动快、占用少、部署方便、镜像可移植、密度高。
- 不足：隔离性弱于虚拟机，管理复杂，依赖 Linux 内核，生态和安全要求更高。

### 3 容器还能进一步轻量化吗？方式是什么？

可以。方式是为应用定制极简内核或 unikernel，使应用与最小运行环境绑定，减少不必要系统组件。

### *学习通限定 4 为什么 Docker 比传统虚拟化快？

因为 Docker 共享宿主机内核，不需要完整客户操作系统和硬件模拟，资源占用少，文件系统和启动过程更轻。

# Ch5 分布式存储

## 课内复习

### *1 分布式存储的定义是什么？

分布式存储是把多台普通计算机或服务器通过网络连接，对外提供一个整体存储服务的系统。

特性：高性能、可扩展、低成本、易用。

### *学习通限定 1.1 集中式存储的定义是什么？

集中式存储把数据集中保存在中心节点，由中心节点统一管理和访问。常见类型：DAS、NAS、SAN。

### *2 分布式存储有哪几种类型？

按系统类型：分布式文件系统、分布式 Key-Value 系统、分布式表系统、分布式数据库。  
按数据类型：结构化、半结构化、非结构化。

### *3 SAN 和 NAS 的区别是什么？

- SAN：存储区域网络，提供块级存储，常用 FC/SCSI，性能高，适合企业级应用。
- NAS：网络附加存储，基于 TCP/IP 提供文件级共享，易扩展，适合文件共享。

一句话：**SAN 是块存储，NAS 是文件存储**。

### 4 比较不同文件系统的特点

- 单机文件系统：单机磁盘，多用户/多进程访问，重 I/O 响应。
- 网络文件系统：通过网络共享文件，如 NFS、AFS、NAS，重共享访问。
- 并行文件系统：面向高性能并行 I/O，如 Lustre，重并行带宽。
- 分布式文件系统：面向海量数据和容错，如 GFS、HDFS，重扩展和副本。

### *学习通限定 5 HDFS 与传统文件系统的区别

- HDFS：分布式、可扩展、容错强，适合大文件批处理和高吞吐，低延迟/小文件较弱。
- 传统文件系统：多为单机或局部网络，强一致、低延迟，适合普通文件操作。

## 课外思考

### 1 是否存在一种文件系统能应对所有类型文件存储？为什么？

不存在。不同数据在规模、访问模式、一致性、延迟、吞吐上的需求不同，只能针对场景选择合适系统。

### 2 Paxos 的原理和机制是什么？

Paxos 是解决分布式一致性的协议，通过多数派投票让多个节点对一个值达成一致。

核心角色：

- Proposer：提出提案。
- Acceptor：接受提案，超过半数才通过。
- Learner：学习并同步最终结果。

流程：Prepare 准备承诺 → Accept 接受提交；原则是**一旦多数派确定一个值，后续不能被改掉**。

# Ch6 云计算网络

## 课内复习

### *1 什么是覆盖网络？

覆盖网络是在原有物理网络之上，通过隧道等方式构建的虚拟/逻辑网络。常见协议：GRE、VLAN、VXLAN、NVGRE、IPSec。

### 2 VXLAN 协议是什么？

VXLAN 是在三层网络上扩展二层网络的隧道技术，用于解决传统 VLAN 数量有限、跨数据中心二层互通等问题。

### *3 什么是大二层网络？

大二层网络是在跨地域或跨数据中心场景下，通过覆盖网络让不同位置的数据中心像处在同一二层网络中，便于迁移、调度和负载均衡。

### 4 Clos 网络结构是什么样的？

Clos 是多级交换网络结构，数据中心常见实现是 Spine-Leaf 架构，用多条等价路径连接接入层和核心层，提高带宽和可靠性。

### *5 SDN 的概念是什么？

SDN 是软件定义网络，通过控制平面与数据平面分离，使网络控制逻辑集中、可编程、可自动化。

关键词：**转控分离、集中控制、开放接口、灵活调度**。

### *学习通限定 5.1 SDN 体系架构并解释

SDN 分三层：

- 应用层：提供业务应用。
- 控制层：控制器形成全网视图，统一配置和调度。
- 数据层：交换机/路由器等设备负责转发。

接口：北向接口连接应用层与控制层；南向接口连接控制层与数据层；东西向接口用于控制器之间通信。

### *6 什么是控制平面和数据平面？

- 控制平面：负责路由、策略、转发逻辑等控制决策。
- 数据平面：负责按照规则实际转发数据包。

### 7 什么是 NFV？

NFV 是网络功能虚拟化，用通用硬件和虚拟化技术以软件形式实现路由、防火墙、负载均衡等网络功能，降低专用硬件成本。

## 课外思考

### 1 SDN 相对传统网络有什么优势？

集中控制、自动化部署、资源池化、灵活调度，能更好支持云计算和虚拟化业务。

### 2 为什么 SDN 还没完全替代传统网络？

SDN 是局部革命，不是完全替代；现网复杂、迁移成本高、可靠性要求高、标准和生态仍需成熟，且集中控制并非所有场景都最优。

### 3 ONOS 和 OpenDaylight 如何推动 SDN？

它们作为开源 SDN 控制器平台，降低研发和部署门槛，促进标准、生态和运营商网络向 SDN 平滑演进。

# Ch8 云原生应用的开发

## 课内复习

### *1 什么是云原生？

云原生是一种构建和运行应用的方法，使应用充分利用云计算的弹性、自动化、可扩展等优势。

### *2 云原生包括哪几个方面？

1. 敏捷基础设施：基础设施即代码，自动化管理资源。
2. 持续交付：快速、安全、频繁发布。
3. DevOps：开发、运维、测试协作和自动化。
4. 微服务：把单体拆成小服务，独立开发、部署和扩展。

### 3 什么是持续集成与持续交付？

- 持续集成 CI：频繁提交代码后自动构建和测试。
- 持续交付 CD：让软件变更随时可安全发布到生产环境。

### 4 云原生的 12 要素是什么？

1. 一份代码库，多份部署  
2. 显式声明依赖  
3. 配置存环境  
4. 后端服务作为附加资源  
5. 构建、发布、运行分离  
6. 无状态进程  
7. 端口绑定服务  
8. 进程模型扩展  
9. 快速启动、优雅终止  
10. 开发/预发布/生产环境尽量一致  
11. 日志作为事件流  
12. 管理任务作为一次性进程

## 课外思考

### *1 云原生应用相对传统云应用的优势是什么？

体积更小、启动更快、资源占用更少、弹性扩展、自动恢复、故障隔离、屏蔽底层差异，交付效率更高。

### 2 为什么 Docker 和 Kubernetes 是云原生最佳实践之一？

Docker 负责把应用和依赖打包成可移植容器；Kubernetes 负责编排、部署、扩缩容、负载均衡和自愈。二者共同支撑云原生的自动化、弹性和可移植。

# Ch10 云端软件

## 课内复习

### *1 云件的概念是什么？

云件是把软件主体和运行环境放在云端，用户通过互联网使用软件服务，使软件不再依赖终端软硬件资源的软件形态。

### *2 云件形态的特征有哪些？

云端运行、按需分配、云端渲染终端显示、无需安装快速启动、网络交付、统一交互平台、文件透明传输。

### *3 云件和 Web 应用、云桌面有什么区别？

- 云件 vs Web 应用：云件全云端计算，输出交互图像，输入鼠标键盘事件；Web 应用主要输出 HTML/CSS，部分依赖终端计算。
- 云件 vs 云桌面：云件只提供软件服务 SaaS，即搜即用；云桌面提供桌面系统服务 DaaS，常需要客户端下载/安装。

### *4 云件系统的分层架构包括哪些内容？

从上到下：云件前端层、数据通信层、容器层、基础设施层、物理层。

## 课外思考

### 1 松耦合冯·诺依曼计算模型和传统模型有什么不同？

传统模型的输入、输出、存储、计算集中在单机；云件模式把输入/输出放终端，存储/计算/控制放云端，通过网络连接，形成松耦合模型。

### 2 云件与桌面虚拟化的本质不同是什么？

桌面虚拟化是把完整桌面映射给用户；云件是应用级虚拟化，只交付具体软件服务，更轻、更面向 SaaS。

### 3 在线实训环境会成为大规模云端服务资源吗？为什么？

会。因为实训环境依赖软件、数据和计算资源，云端统一部署可减少本地配置成本，方便按需使用和规模化管理。

### 4 大型传统桌面软件会以云端软件形式提供服务吗？

会。Matlab、SAS、AutoCAD 等软件资源重、安装复杂，云端化可降低终端要求，实现按需使用和集中维护。

# Hadoop-HDFS

### 1 写数据时 Pipeline 上一个 DataNode 失效，HDFS 如何处理？

HDFS 会关闭出错节点相关链路，从 Pipeline 中移除失效 DataNode，继续向剩余节点写入；NameNode 之后根据副本数不足重新复制数据块到其他 DataNode。

### 2 HDFS 如何保证数据完整性？

1. 安全模式：启动时检查块汇报，达到安全阈值后再提供服务。
2. SecondaryNameNode：周期性合并 FSImage 和 EditLog，辅助恢复元数据。
3. 心跳机制：NameNode 监控 DataNode 存活。
4. 副本机制：节点失效后自动补副本。
5. 校验和：读写传输时用 checksum 检测数据错误。
6. 租约机制：保证同一文件同一时刻只有一个写者。
7. 回滚机制：升级异常时可恢复旧版本。

# MapReduce 题目

## 题目一

### 问题 1 Hadoop MapReduce 如何共享只读文件？

使用 DistributedCache 分布式缓存。它借助 HDFS 把只读文件分发到各任务节点，本质是磁盘缓存，供任务本地读取。

### 问题 2 Combiner 的作用是什么？

Combiner 是 Map 端的本地 Reducer，用于局部汇总/规约，减少 Shuffle 数据量。

### 问题 3 阶段输出

输入：`<k1,15> <k2,21> <k3,24> <k4,30> <k5,49>`  
质因数：15=3×5，21=3×7，24=2×3，30=2×3×5，49=7×7。

| 阶段 | 输出 |
|---|---|
| Map | `<3,15> <5,15> <3,21> <7,21> <2,24> <3,24> <2,30> <3,30> <5,30> <7,49>` |
| Shuffle | `<2,{24,30}> <3,{15,21,24,30}> <5,{15,30}> <7,{21,49}>` |
| Reduce | `<2,54> <3,90> <5,45> <7,70>` |

## 题目二

### 问题 1 Map Task 数目如何决定？

由输入切片 InputSplit 数量决定，通常与文件大小、块大小和切片策略有关。

### 问题 2 Partitioner 的作用是什么？

Partitioner 决定 Map 输出的 key-value 发送给哪个 Reduce Task，默认常按 key 的哈希对 Reduce 数取模。

### 问题 3 阶段输出

输入：`<Tom,Jack> <Jack,Alice> <Jack,Jesse>`。  
目标：由“父母-子女”推出“祖父母-孙子女”。

| 阶段 | 输出/操作 |
|---|---|
| Map | 对每条关系输出两类标记：以父母为 key 输出 `child`，以子女为 key 输出 `parent` |
| Map 输出 | `<Tom,(child,Jack)> <Jack,(parent,Tom)> <Jack,(child,Alice)> <Alice,(parent,Jack)> <Jack,(child,Jesse)> <Jesse,(parent,Jack)>` |
| Shuffle | 按 key 聚合：`Tom:{child Jack}`；`Jack:{parent Tom, child Alice, child Jesse}`；`Alice:{parent Jack}`；`Jesse:{parent Jack}` |
| Reduce | 只在同一 key 同时有 parent 和 child 时连接，输出 `<Tom,Alice> <Tom,Jesse>` |
