## 简答题优先清单

### Ch1 云计算概述

来源：`1云计算概述/CH1-云计算概述-2023.pdf`，第 60 页。

1. 大数据现象是怎么形成的？

   答：大数据由互联网、移动终端、物联网、传感器、业务系统等持续产生海量数据形成。其根本原因是数据采集成本下降、网络连接普及、存储计算能力提升，以及线上业务规模扩大。

2. 新摩尔定律的含义是什么？

   答：新摩尔定律强调数据量和计算需求快速增长，计算能力不再只依赖单机芯片性能提升，而更多依赖分布式、并行化和云端资源池化来获得持续扩展能力。

3. 云计算有哪些特点？

   答：弹性伸缩、快速部署、资源抽象、按需自助、按量计费、宽带网络访问、资源池化。
   简记：**弹、快、抽、按、网、池**。

4. 云计算可以分为哪几类？

   答：按部署方式分为公有云、私有云、社区云、混合云、行业云；按服务类型分为 IaaS、PaaS、SaaS。

5. 云计算技术体系结构可以分为哪几层？

   答：通常可分为物理资源层、资源虚拟化层、云管理/平台层、服务接口层、应用层。也可对应 IaaS、PaaS、SaaS 三个服务层次。

6. 在性价比上云计算相比传统技术为什么有优势？

   答：云计算通过规模化数据中心、资源池化、虚拟化、多租户共享和按需付费降低单位成本；用户无需一次性购买大量硬件，可按业务量弹性使用，减少闲置和维护成本。

### Ch2 分布式计算

来源：`2分布式管理/CH2-分布式计算-1.pdf`，第 53 页；同内容也见 `CH2-分布式计算-复习.pdf`。

1. 分布式计算的定义和特征是什么？

   答：分布式计算是多个软件或多台计算机通过网络协同完成任务的计算方式。特征是资源共享、并行处理、负载均衡、可扩展、高可靠，但也带来通信、同步和一致性问题。

2. 什么是 ACID 原则？

   答：ACID 是事务四原则：原子性 A，要么全做要么全不做；一致性 C，事务前后满足约束；隔离性 I，并发事务互不干扰；持久性 D，提交后结果永久保存。

3. 什么是 CAP 理论？

   答：CAP 指一致性 C、可用性 A、分区容错性 P。分布式系统发生网络分区时，最多只能同时保证其中两个，通常必须保 P，再在 C 和 A 之间取舍。

4. 什么是 BASE 理论？

   答：BASE 是对 CAP 的工程化取舍：基本可用 Basically Available、软状态 Soft State、最终一致 Eventual Consistency。它放弃强一致，追求系统可用和最终一致。

5. 如何理解最终一致性？

   答：最终一致性允许不同副本短时间不一致，但在没有新更新并经过同步后，所有副本最终一致。简记：**过程松，结果紧**。

6. 各类分布式存储、分布式计算的区别与联系是什么？

   答：分布式存储包括结构化、非结构化、半结构化、内存存储、NewSQL 等，重点解决数据保存、复制和容错；分布式计算包括 MPI、MapReduce/Dataflow、图计算等，重点解决任务拆分、调度和并行执行。二者常结合使用，计算尽量靠近数据以减少网络开销。

课外思考，来源：`CH2-分布式计算-1.pdf`，第 54 页。

1. 在日常生活中，为什么我们所接触到的分布式系统越来越多了？

   答：因为业务规模、用户数量和数据量不断增大，单机难以支撑；分布式系统能提高容量、可用性、容错性和扩展性，也便于模块化开发和快速发布。

2. CAP 定理中的几个关键因素为什么不能同时保证？不同的组合有什么样的应用场景？

   答：网络分区时，如果继续响应请求可能读到旧数据，会牺牲一致性；如果等待同步再响应，会牺牲可用性。CP 适合银行、强一致数据库；AP 适合 DNS、购物车、社交系统；CA 只适合无网络分区或单机/局域可靠场景。

3. 通过了解区块链的背景，说说你所理解的区块链作为一种分布式系统背后的全新理念。

   答：传统分布式系统默认节点可信、协作；区块链默认节点不完全可信，通过共识、密码学和不可篡改账本实现“无需中心的信任”。它重点解决节点本身不可靠的问题。

### Ch3 云计算架构

来源：`6云计算架构/CH3-云计算架构.pdf`，第 27 页；同内容也见 `CH3-云计算架构-课后习题.pdf`。

1. 云计算中的工作负载有哪几种模式？它们的特征是什么？

   答：四种模式：时开时停，资源间歇使用；用量迅速增长，业务持续扩张；瞬时暴涨，短时峰值明显；周期性增减，负载按规律波动。云计算可按这些负载弹性扩缩容，减少超配浪费。

2. 什么是 REST 设计风格？

   答：REST 是面向 Web 的架构风格，强调统一接口、资源化表示、客户机/服务器分离、无状态连接、组件独立发布和良好伸缩性。

3. 如何理解“云栈”和“云体”的概念？

   答：云体是云计算的物质基础，包括服务器、网络、存储等资源集合；云栈是运行在云体之上的云平台和软件环境，负责应用发布、运行、监控、调度和伸缩。简记：**云体是资源，云栈是平台**。

4. 什么是软件定义的数据中心？它的特点是什么？

   答：软件定义数据中心 SDDC 是把计算、存储、网络、安全等资源虚拟化，并由软件统一管理和交付的数据中心。特点：标准化、自动化、自适应、统一管理、恢复能力强、资源利用率高。

课外思考，来源：`CH3-云计算架构.pdf`，第 28 页。

1. 云计算的架构是如何演化的？

   答：大致经历中央主机架构、C/S 架构、中间层架构、B/S 架构、C/S 与 B/S 混合、SOA 面向服务架构，最终发展为资源池化、服务化、弹性化的云计算架构。

2. 如何理解“软件定义一切”的说法？

   答：软件定义一切是指通过软件抽象、控制和调度硬件、网络、存储、数据中心等资源，使系统功能和资源分配由软件灵活决定。其基础是硬件能力提升和网络连接普及。

动手实践，来源：`CH3-云计算架构-课后习题.pdf`，第 3 页。

1. 通过 OpenStack 官方网站了解 OpenStack 作为开源项目的情况。

   答：实践要点：OpenStack 是开源云计算平台，用于建设和管理私有云/公有云，核心能力是统一管理计算、网络、存储和镜像等资源。

2. 通过 Packstack 工具安装并体验 OpenStack。

   答：实践要点：Packstack 是基于 Puppet 的 OpenStack 自动化部署工具，适合快速搭建测试环境，体验虚拟机创建、网络配置、镜像和存储管理流程。

### Ch4 虚拟化技术

来源：`7虚拟化技术/4-3 课后作业.pdf`，第 1 页。

1. 什么是虚拟化技术？该技术有哪三种类型？

   答：虚拟化是对计算资源进行抽象，把物理资源转换为可管理、可分配的逻辑资源。三种类型：服务器虚拟化、网络虚拟化、桌面虚拟化。

2. 全虚拟化技术和半虚拟化技术的区别是什么？

   答：全虚拟化不需要修改客户操作系统，兼容性好但开销较大；半虚拟化需要修改或适配客户操作系统，与虚拟化层协作，性能可能更好但兼容性较差。

3. 什么是寄居架构虚拟机监控器？什么是裸金属架构虚拟机监控器？两者的区别是什么？

   答：寄居架构 Type 2 运行在宿主操作系统之上，如 VirtualBox；裸金属架构 Type 1 直接运行在物理硬件上，如 ESXi、Hyper-V。前者部署简单、适合桌面测试；后者性能和隔离更好，适合生产服务器。

4. 硬件虚拟化技术有哪些代表？

   答：代表包括 CPU 硬件辅助虚拟化 Intel VT-x/AMD-V，I/O 虚拟化 SR-IOV，以及 GPU、FPGA、RDMA、NVM 等资源虚拟化。

5. 什么是轻量级虚拟化技术？其代表是什么？

   答：轻量级虚拟化是在共享宿主机内核的基础上隔离应用运行环境的技术。代表是容器，典型实现是 Docker。

课外思考，来源：`7虚拟化技术/4-3 课后作业.pdf`，第 2 页。

1. 虚拟化技术对提高计算资源的利用率究竟带来了怎样的好处？

   答：虚拟化可把多个系统整合到同一资源池中，实现按需分配、动态迁移、隔离运行和统一管理，从而减少硬件闲置、提高部署效率并降低成本。

2. 轻量级虚拟化技术相对于传统虚拟化技术的优势和不足是什么？

   答：优势是启动快、占用少、部署方便、镜像可移植、密度高；不足是隔离性弱于虚拟机，内核共享带来安全风险，复杂集群需要编排工具管理。

3. 容器的轻量级虚拟化技术还能进一步轻量化吗？有什么样的方式？

   答：可以。可通过 unikernel、极简运行时、精简基础镜像等方式，只保留应用运行所需的最小内核和依赖，进一步减少体积与启动开销。

动手实践，来源：`7虚拟化技术/4-3 课后作业.pdf`，第 3-4 页。

1. 通过 KVM 官方网站下载并安装使用 KVM，进一步了解 KVM 的原理。

   答：实践要点：KVM 是 Linux 内核中的硬件辅助虚拟化模块，配合 QEMU 提供设备模拟和虚拟机管理，适合学习 Type 1/内核型虚拟化原理。

2. 通过 Phoronix 基准测试程序对一个 KVM 系统的性能进行评测和比较。

   答：实践要点：用 CPU、内存、磁盘、网络等指标对比宿主机与虚拟机性能，理解虚拟化开销主要来自设备模拟、I/O 和调度。

3. 通过 Docker 官方网站下载并安装使用最新的 Docker，进一步了解 Docker 的原理。

   答：实践要点：Docker 利用 namespace 做隔离、cgroups 做资源限制、镜像分层做分发，适合体验容器构建、运行和发布流程。

4. 通过基准测试程序对容器和传统虚拟机的性能进行评测和比较。

   答：实践要点：容器通常启动更快、资源占用更低、接近原生性能；虚拟机隔离更强、系统兼容性更好，但启动和资源开销更大。

### Ch5 分布式存储

来源：`8分布式存储/CH5-分布式存储-3.pdf`，第 72 页。

1. 集中式存储的定义是什么？分布式存储的定义是什么？

   答：集中式存储是把数据集中存放在一个或少数中心节点，由中心统一管理；分布式存储是把多台服务器通过网络连接，对外提供一个统一的整体存储服务。

2. 分布式存储有哪几种类型？分别适合处理哪些类型的数据？

   答：分布式文件系统适合大文件和非结构化数据；分布式 Key-Value 系统适合简单键值和高并发访问；分布式表系统适合半结构化宽表数据；分布式数据库适合结构化数据、事务和查询。

3. SAN 和 NAS 的区别是什么？

   答：SAN 是存储区域网络，提供块级存储，常用 FC/SCSI，性能高，适合企业数据库等场景；NAS 是网络附加存储，提供文件级共享，基于 TCP/IP，易用易扩展。简记：**SAN 是块，NAS 是文件**。

4. 比较不同文件系统的特点。

   答：单机文件系统重低延迟本地访问；网络文件系统重多客户端共享；并行文件系统重高性能并行 I/O；分布式文件系统重海量数据、容错、副本和横向扩展。

课外思考，来源：`8分布式存储/CH5-分布式存储-3.pdf`，第 73 页。

1. 是否存在一种文件系统能够应对所有类型的文件存储？为什么？

   答：不存在。因为不同数据在文件大小、访问模式、延迟、吞吐、可靠性和一致性上的需求不同，只能针对场景选择合适文件系统。

2. Paxos 的原理和机制是什么？

   答：Paxos 是通过多数派投票在不可靠分布式环境中达成一致的协议。角色包括 Proposer、Acceptor、Learner；流程为 Prepare 承诺和 Accept 接受，核心原则是多数派一旦确定一个值，后续不能被破坏。

动手实践，来源：`8分布式存储/CH5-分布式存储-3.pdf`，第 74-75 页。

1. 通过 Ceph 官方网站下载并安装使用最新的软件，进一步了解 Ceph 的原理。

   答：实践要点：Ceph 是统一分布式存储系统，可提供对象、块、文件存储，核心是 RADOS 和 CRUSH，实现无中心的数据分布与容错。

2. 理解并实践 CRUSH。

   答：实践要点：CRUSH 是 Ceph 的数据放置算法，根据集群拓扑和规则计算对象位置，避免中心元数据瓶颈，并支持故障域感知。

3. 通过 Hadoop 官方网站下载并安装使用最新的 Hadoop 软件，进一步了解 HDFS 的工作原理。

   答：实践要点：HDFS 采用 NameNode 管理元数据、DataNode 存储数据块，依靠大块、流水线写入、副本和心跳机制实现高吞吐与容错。

### Ch6 云计算网络

来源：`9云计算网络/06云计算网络.pptx`，第 34 张。

1. 什么是覆盖网络？

   答：覆盖网络是在已有物理网络之上，通过隧道等方式构建的虚拟/逻辑网络。常见协议有 GRE、VLAN、VXLAN、NVGRE、IPSec。

2. VXLAN 协议是什么？

   答：VXLAN 是一种通过 UDP 隧道在三层网络上扩展二层网络的技术，可突破传统 VLAN 数量限制，支持跨数据中心二层互通和租户隔离。

3. 什么是大二层网络？

   答：大二层网络是让跨机房、跨数据中心的主机处于同一二层网络中的技术，便于虚拟机迁移、统一调度和负载均衡，通常依赖覆盖网络实现。

4. Clos 网络结构是什么样的？

   答：Clos 是多级交换网络结构，数据中心常见为 Spine-Leaf 架构。Leaf 连接服务器，Spine 连接所有 Leaf，提供多条等价路径、高带宽和高可靠。

5. 软件定义网络（SDN）的概念是什么？

   答：SDN 是把网络控制平面和数据平面分离，由控制器集中控制网络行为，并通过开放接口实现可编程、自动化和灵活调度的网络架构。

6. 什么是控制平面和数据平面？

   答：控制平面负责路由、策略、流表下发等决策；数据平面负责按照控制规则转发数据包。SDN 的核心就是二者分离。

7. 什么是网络功能虚拟化（NFV）？

   答：NFV 是用通用硬件和虚拟化技术，以软件方式实现路由、防火墙、负载均衡、网关等网络功能，减少对专用硬件设备的依赖。

课外思考，来源：`9云计算网络/06云计算网络.pptx`，第 36 张。

1. SDN 相对于传统网络有些什么优势？

   答：SDN 具有集中控制、开放可编程、自动化配置、资源池化、灵活调度等优势，更适合云计算环境中的网络快速部署和弹性调整。

2. 如果 SDN 是下一代网络技术，为什么直到现在 SDN 还没能替代传统网络？

   答：因为现有网络规模大、设备复杂、迁移成本高，运营级可靠性要求严格；同时 SDN 标准、生态、安全和运维体系仍需成熟，集中控制也不是所有场景都最优。

3. ONOS 和 OpenDaylight 这样的开源项目是如何推动 SDN 技术的？

   答：它们提供开源 SDN 控制器平台，降低研发和部署门槛，促进标准接口、生态兼容和运营商网络平滑演进。

动手实践，来源：`9云计算网络/06云计算网络.pptx`，第 37-38 张。

1. 通过 Mininet 官方网站下载并安装使用最新的软件，进一步熟悉 Mininet 的操作。

   答：实践要点：Mininet 可在单机上模拟主机、交换机、链路和控制器，适合快速搭建 SDN 实验网络。

2. 在 Mininet 中安装 OpenFlow，并测试其性能。

   答：实践要点：OpenFlow 是 SDN 南向接口协议，用于控制器向交换机下发流表；测试重点是连通性、时延、吞吐和流表变化。

3. 通过 OpenDaylight 官方网站进一步了解 OpenDaylight。

   答：实践要点：OpenDaylight 是模块化开源 SDN 控制器，支持多种南向协议和北向 API，可统一控制异构网络设备。

4. 利用 Mininet 和 OpenDaylight 搭建一个完整的 SDN 环境，并测试其性能。

   答：实践要点：Mininet 模拟数据平面，OpenDaylight 作为控制平面，通过 OpenFlow 下发流表，验证 SDN 的转控分离和集中控制。

### Ch7 云计算安全

来源：`10云计算安全/07云计算安全.pptx`，第 56 张。

1. 云计算的安全技术框架包含哪些内容？

   答：主要包括身份认证与访问控制、数据安全与隐私保护、虚拟化安全、网络安全、主机与应用安全、安全审计与合规、容灾备份和可信计算等。

2. 虚拟化软件栈面临哪些安全威胁？

   答：主要威胁有 Hypervisor 漏洞、虚拟机逃逸、虚拟机间侧信道攻击、恶意镜像、虚拟网络监听、资源争用导致的拒绝服务、管理接口被攻击等。

3. 虚拟化软件栈有哪些防御措施？

   答：措施包括最小化和加固 Hypervisor、及时补丁、强隔离、镜像签名与扫描、访问控制、虚拟网络隔离、资源限额、日志审计、入侵检测和可信启动。

4. 安全云存储系统有哪些关键技术？

   答：关键技术包括数据加密、密钥管理、访问控制、完整性校验、冗余备份、可用性保障、隐私保护、审计追踪和安全删除。

课外思考，来源：`10云计算安全/07云计算安全.pptx`，第 57 张。

1. 云数据的安全与隐私问题是否会阻止云计算的发展？

   答：不会阻止，但会影响发展速度和应用范围。通过加密、访问控制、合规审计、可信计算和隐私保护技术，可以降低风险并推动云计算继续发展。

2. 怎样在云计算的便捷性和云计算的安全问题上进行取舍？

   答：应按业务敏感度分级取舍：普通业务优先便捷和成本，核心数据加强加密、隔离和审计；总体原则是风险可控、权限最小、数据分级、合规优先。

动手实践，来源：`10云计算安全/07云计算安全.pptx`，第 58-59 张。

1. 通过 HElib 项目网站进一步了解并使用 HElib。

   答：实践要点：HElib 是同态加密库，可在密文上直接计算，适合理解“数据不解密也能处理”的云隐私保护思想。

2. 通过 FHE-CODE 项目网站进一步了解并使用 FHE-CODE。

   答：实践要点：FHE-CODE 用于学习全同态加密实现，重点理解密文计算、噪声控制和性能开销。

### Ch8 云原生应用开发

来源：`11云原生应用的开发/08云原生应用的开发.pptx`，第 80 张。

1. 什么是云原生？

   答：云原生是一种构建和运行应用的方法，使应用充分利用云计算的弹性、自动化、可扩展和高可用能力。

2. 云原生包括哪几个方面的内容？

   答：主要包括敏捷基础设施、持续交付、DevOps、微服务，也常与容器、服务网格、声明式 API、自动化运维结合。

3. 什么是持续集成与持续交付？

   答：持续集成 CI 是频繁提交代码后自动构建和测试；持续交付 CD 是让软件变更随时可以安全发布到生产环境。

4. 云原生的 12 要素是什么？

   答：一份代码库、多份部署；显式依赖；配置存环境；后端服务作附加资源；构建/发布/运行分离；无状态进程；端口绑定；进程模型扩展；快速启动优雅终止；开发预发布生产环境一致；日志作事件流；管理任务作一次性进程。

课外思考，来源：`11云原生应用的开发/08云原生应用的开发.pptx`，第 81 张。

1. 相对于传统云应用，云原生应用的优势是什么？

   答：云原生应用体积更小、启动更快、资源占用更少、可移植性更好，支持弹性扩展、故障自愈、快速交付和自动化运维。

2. 为什么 Docker 和 Kubernetes 技术成为云原生落地的最佳实践之一？

   答：Docker 负责把应用和依赖打包成可移植容器；Kubernetes 负责容器编排、部署、扩缩容、负载均衡和自愈，二者共同支撑云原生的自动化和弹性。

动手实践，来源：`11云原生应用的开发/08云原生应用的开发.pptx`，第 82-83 张。

1. 通过 Node.js 项目网站了解并使用 Node.js 进行编程。

   答：实践要点：Node.js 是基于 V8 的 JavaScript 运行时，适合构建高并发 I/O 型 Web 服务。

2. 在 Docker 环境中部署 Node.js，并开发或部署一个简单的网站系统。

   答：实践要点：将 Node.js 应用写入镜像，通过 Dockerfile 声明依赖、端口和启动命令，再用容器运行，实现环境一致和快速部署。

3. 阅读云端 Web 应用自动扩展机制相关论文。

   答：实践要点：自动扩展通常根据 CPU、内存、请求量、队列长度等指标触发扩容/缩容，目标是在性能和成本之间平衡。

4. 理解面向云计算软件工程的挑战与未来方向。

   答：实践要点：挑战包括分布式复杂性、可观测性、可靠性、安全、成本控制和持续交付；方向是自动化、智能运维、云原生架构和平台工程。

## 考前最短背诵清单

- 云计算：按需服务、资源池化、弹性伸缩、按量计费、宽带访问。
- 分类：部署看公私混社，服务看 IaaS/PaaS/SaaS。
- CAP：分区必选 P，C 和 A 二选一；CP 重一致，AP 重可用。
- BASE：基本可用、软状态、最终一致。
- 云栈/云体：云体是资源，云栈是平台。
- SDDC：数据中心资源虚拟化、软件统一管理。
- 虚拟化：全虚拟化兼容好，半虚拟化性能好，硬件辅助降开销。
- Hypervisor：Type 1 裸金属，Type 2 寄居。
- 容器：共享内核，所以快、省、轻；隔离弱于虚拟机。
- 存储：SAN 块存储，NAS 文件存储，HDFS 大文件高吞吐。
- 网络：Overlay 建逻辑网，VXLAN 扩二层，SDN 转控分离，NFV 功能软件化。
- 云原生：容器、微服务、DevOps、持续交付；Docker 打包，K8s 编排。
